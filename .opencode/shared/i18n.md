# I18N COMPLIANCE - MANDATORY FOR EVERY CHANGE

Semua teks yang terlihat user WAJIB pakai i18n. Tidak ada pengecualian tanpa approval Tech Lead.

## Stack Wajib

- Library: i18next + react-i18next
- Bahasa sumber kebenaran: `id` (Indonesia)
- Bahasa wajib lain: `en` (English)
- Lokasi file: `src/i18n/locales/{id,en}/[namespace].json`
- Namespace mengikuti fitur: `common`, `auth`, `home`, `profile`

## Aturan Wajib

1. DILARANG hardcode teks di JSX/TSX:
   SALAH: <Text>Login</Text>, placeholder="Email", accessibilityLabel="Kembali"
   BENAR: <Text>{t('auth:login.title')}</Text>

2. Naming key: lowercase, dot-separated, berdasarkan makna, bukan teks.
   SALAH: `login_text_1`, `masuk`
   BENAR: `auth:login.title`, `auth:login.submitButton`, `auth:login.error.invalidEmail`

3. Semua key di `id` WAJIB ada pasangannya di `en` dengan struktur persis sama. Tidak boleh ada key hilang / key berlebih.

4. DILARANG menggabungkan string manual untuk kalimat:
   SALAH: `t('common:hello') + ' ' + name`
   BENAR: Pakai interpolasi: `t('common:greeting', { name })`
   File bahasa: "greeting": "Halo, {{name}}"

5. Plural, tanggal, angka, mata uang WAJIB pakai formatter, bukan teks manual:
   - Plural: i18next plural form (`_one`, `_other`)
   - Tanggal/angka: `Intl.DateTimeFormat`, `Intl.NumberFormat` dengan locale aktif

6. Teks dari API/Backend yang user-facing harus dimapping ke key i18n di frontend. Jangan tampilkan error mentah dari server langsung ke UI.

7. Designer wajib menyerahkan Copy Table di 03-UI-SPEC.md. Developer dilarang mengarang teks sendiri tanpa key.

## Bukti Wajib

Setiap perubahan harus lulus script `.opencode/scripts/check-i18n.sh` dengan hasil PASS.
Jika gagal: Status BLOCKED, dilarang lanjut ke fase berikutnya.
